# Echo Tech — instructions for AI coding agents

This is the single source of truth for any AI assistant working in this repo (Claude Code, Codex, Gemini, Copilot, Cline, Cursor, Antigravity). Tool-specific files (`CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.cursor/rules/`, `.clinerules/`) only point here. Edit this file, not those.

## What this project is

The website of **Echo Tech**, a startup selling: network infrastructure, CCTV systems, websites, mobile applications, business systems (CRMs, internal tools), business automation, data analysis and dashboards, and domains and hosting. More services will be added; they are data, not code (see Adding a service below). Clients are worldwide. The site is bilingual (English is the default at `/`, Arabic at `/ar/`; `public/_redirects` sends the old `/en/` URLs to `/`), has light and dark themes, and runs on a **Cloudflare Worker with static assets** (Git integration: build `npm run build`, deploy `npx wrangler deploy`) (domain `echo-tech.website`, repo `melkadi84/echotech`, branch `main`).

First reference client: **Joy Zone** (joy-zone.net), a children's indoor play centre in Alexandria. We built its website and an internal CRM.

The owner writes in Egyptian Arabic. Reply to the owner in Egyptian Arabic unless asked otherwise. Code, comments and commit messages are in English.

## Stack and layout

No framework. Static HTML generated by a small Node script, plain CSS and JS, one Worker entry.

```
src/build.mjs            generates public/*.html, sitemap, robots, manifest, _headers (+ JSON-LD schema)
src/content/ar.json      ALL Arabic copy
src/content/en.json      ALL English copy (same keys as ar.json). services.items[].page feeds each service page; `pages` holds shared sub-page strings
src/site.config.json     domain, email, WhatsApp, Turnstile key, social links, theme colours
public/                  deployed output (committed). Every index.html (home, work/, services/<id>/, in ar and en) is GENERATED
public/assets/css/site.css   design tokens + components
public/assets/js/site.js     behaviour (theme, menu, ripples, form, loader)
public/assets/js/sections.js services picker (tabs) and client strip controls
public/assets/js/showcase.js concept demos (dashboard, automation, app, booking list)
public/assets/js/motion.js   scroll reveals and pointer tilt
public/assets/clients/       optional client logos: joy-zone.svg|png|webp (build shows initials if absent)
public/assets/brand/     logo files, app icons, OG image
brand/                   brand source SVGs
src/worker.js            Worker: serves ASSETS, handles POST /api/contact (validates, rate-limits, stores in D1)
wrangler.jsonc           Worker + static assets config; schema.sql is the D1 schema
docs/                    BRAND.md, ANIMATIONS.md, CONTENT.md, DEPLOY.md, SKILLS.md
.claude/                 settings.json (plugins) and agents/code-simplifier.md
```

Commands: `npm run build` (regenerate HTML), `npm run dev` (build + local Worker), `npm run deploy`.

## Hard rules

1. **Never hand-edit `public/index.html`, `public/ar/index.html`, `sitemap.xml`, `_headers`, `_redirects` or `site.webmanifest`.** Change `src/` and run `npm run build`, then commit the regenerated files.
2. **Keep Arabic and English in sync.** Every key in `ar.json` exists in `en.json` and the reverse. A change to one language is incomplete until the other is updated.
3. **RTL correctness.** Use CSS logical properties (`inline-start`, `margin-inline`, `inset-inline-end`, `padding-block`). Never `left`/`right` for layout. Test every UI change in both `/` and `/ar/`.
4. **Content Security Policy is strict.** No inline `style=""` attributes, no inline event handlers, no new inline `<script>` (the one theme script is hash-allowed by the build). Set styles from JS through the CSSOM (`el.style.x = ...`) or classes. New external origins must be added to the CSP in `src/build.mjs`.
5. **Both themes always.** Every colour comes from a CSS variable in `site.css`. Check contrast (WCAG AA) in light and dark.
6. **Honest content.** Never invent testimonials, metrics, client names, certifications, partnerships or prices. Add a client or quote only with the owner's confirmation and the client's permission. `work.testimonials` stays an empty array until real quotes exist. Policies written in FAQ answers (support, ownership of accounts) are owner decisions, so confirm before changing them.
7. **Accessibility floor.** Semantic landmarks, one `h1`, visible focus, labels on every field, `aria-live` for form status, keyboard-operable menu, 44px touch targets on mobile.
8. **Motion rules.** Every animation respects `prefers-reduced-motion` and uses `transform`/`opacity` only (the concept demos also set bar heights through `transform`). Owner-approved (Nov 2026): richer motion is allowed when it helps the visitor understand or act, namely staggered reveals on scroll (`motion.js`), pointer tilt on device frames, and the interactive demos in `showcase.js`. Under reduced motion none of that runs and content is shown at once. The client strip in `#work` must still pause on hover/focus, have a visible pause button, pause off-screen, and stop entirely under reduced motion. See `docs/ANIMATIONS.md`.
9. **Secrets never enter the repo.** Turnstile secret, webhook URLs and D1 ids live in Cloudflare settings or `.dev.vars` (git-ignored). `src/site.config.json` holds only public values.
10. **No new dependencies** without a clear reason. The site has none at runtime.

11. **Section-by-section scrolling.** Scroll is never free, in any mode: `html` uses `scroll-snap-type: y mandatory` with smooth gliding, and every `main > section` is at least one screen tall (`min-height: calc(100svh - 4.25rem)`) with `scroll-snap-align: start`; the footer snaps to its end. Keep new sections to one idea per screen. On screens up to 860px, long lists (steps, principles, services, chips, footer links) are swipeable carousels with the next card peeking in, not tall columns. Under reduced motion the glide is off.

## Brand (details in `docs/BRAND.md`)

The mark is a solid disc with two fading rings trailing behind it: an echo. Primary **Cobalt `#1D4ED8`**, secondary **Sky `#60A5FA`**. Font: **Readex Pro** (Arabic and Latin). Do not recolour, rotate, outline or add effects to the logo. Wordmark is "ECHO TECH" in Latin, "إيكو تك" in Arabic.

Design stance: the theme decides everything. Light mode is light on every section, dark mode is dark on every section (the `.stage` class only marks hero-style bands; it is dark only under `[data-theme="dark"]`). Concept device frames stay dark in both themes on purpose. One memorable element: the signal map in the hero, where a pulse leaves the core disc and visits every service (its nodes link to the service pages; the services section below is the keyboard-accessible route). Everything else stays quiet: hairline dividers, one panel for the selected service, no card grids, no gradient washes (the faint dot grid in the hero is a texture), no all-caps eyebrow labels, no numbered markers unless the content is truly a sequence.

## Copy style

Plain language, active voice, sentence case, specific over clever. Buttons name the action ("Request a quote", "Send message"). Errors say what happened and how to fix it. Arabic copy is natural modern standard Arabic, not a literal translation.

## Code standards

- Vanilla ES modules and plain JS, no framework, no TypeScript, no bundler. Arrow functions are fine. Prefer small named functions over clever one-liners and avoid nested ternaries.
- `try/catch` is allowed where the browser can fail (storage, network, View Transitions). Do not swallow errors elsewhere.
- CSS: tokens as variables on `:root` and `[data-theme="dark"]`, logical properties, no `!important` outside the reduced-motion block, no ID selectors for styling.
- Keep `site.js` dependency-free and under about 300 lines; split by feature before it grows past that.
- Comments explain why, not what.

## Skills and agents

Design skills and the `code-simplifier` agent are configured in `.claude/` and documented in `docs/SKILLS.md`. Project rules in this file and `docs/BRAND.md` override any skill's defaults. Run the `code-simplifier` agent after a batch of code changes.

## Git workflow

Project rule from the owner: **every change is committed, pushed and merged to `main`.** Work on a short-lived branch, open a PR, merge it, or push straight to `main` for small changes. Before committing:

1. `npm run build` and confirm `git status` shows the regenerated `public/` files.
2. Open both pages and check light/dark and RTL/LTR.
3. Write a clear commit message in the imperative ("Add FAQ entry about support hours").

Do not leave work uncommitted at the end of a session.

## Definition of done

- Both languages updated; build run; generated files committed.
- Works at 360px, 768px and 1440px widths, in light and dark, with reduced motion on.
- No console errors; CSP not violated.
- Docs updated if behaviour, tokens, content structure or deployment changed.
